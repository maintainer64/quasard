# LLM, RU/EN и опциональные MCP-инструменты

[Основная настройка](../README.md) · [Сеть и Docker](NETWORKING.md) · [Проверки и ограничения](parity.md)

Сервер использует OpenAI-совместимый Chat Completions API. Без MCP обычные ответы идут через SSE; MCP включается отдельно. Для первого подключения колонки в README используется локальный `base_url = "echo"`, без внешних вызовов. Настоящий LLM настраивается после проверки DNS, TLS и речи. Внешние платные API тесты не вызывают.

## Endpoint, ключ и Docker

`llm.base_url` — корень API, например `https://api.groq.com/openai/v1`; backend добавляет `/chat/completions`. `model` должен существовать у выбранного провайдера. Ключ задаётся приватным `llm.api_key`, ссылкой `llm.api_key_env` на переменную контейнера либо `GROQ_API_KEY` окружения **контейнера**. Пустой ключ использует этот env fallback, а без него отправляется `Bearer none` для совместимости с локальными API.

Окружение компьютера не передаётся автоматически. Добавьте ключ в `environment` локального Compose override и пересоздайте сервис; не публикуйте вывод `docker compose config` с секретами. `llm.timeout_s` ограничивает отдельный completion, включая tool-enabled режим. Провайдер, model ID и тариф выбирает оператор; включение внешнего API может создавать расходы.

`127.0.0.1` из контейнера указывает на сам контейнер. Для LLM на Mac/Windows с Docker Desktop обычно нужен `host.docker.internal`; на Linux — отдельно настроенный host access или общая контейнерная сеть. Это относится к LLM HTTP API; у MCP строже правила endpoint, описанные ниже.


## Настройки по device_id

Общая секция `[llm]` задаёт значения по умолчанию. Для колонки добавьте
в тот же файл точное значение ID из `/_status` (поля devices/connections)
или заголовка `X-UPRX-DEVICE-ID` её WebSocket-соединения:

```toml
[llm]
base_url = "https://ha.gubanov.site:20128/v1"
model = "your-model"
api_key = "" # Общий ключ в приватном конфиге или существующий GROQ_API_KEY fallback.

[devices."DEVICE_ID_KITCHEN".llm]
api_key_env = "KITCHEN_LLM_KEY"
model = "kitchen-model"
max_tokens = 200

[devices."DEVICE_ID_BEDROOM".llm]
api_key_env = "BEDROOM_LLM_KEY"
temperature = 0.3
```

Переменные с ключами должны быть переданы **в контейнер**. Указанный
api_key_env с отсутствующим/пустым значением останавливает запуск с ошибкой,
вместо перехода на общий ключ. Имена переменных могут быть любыми корректными
env-именами. Поддержан и общий `llm.api_key_env`.

Вместо api_key_env можно указать `api_key = "..."` прямо в приватном TOML,
например в config.toml.encrypted, который существующий cloud-деплой
расшифровывает через Vault. В одной секции используйте один способ задания
ключа. Переопределение ключа у устройства заменяет общий способ его задания.

Доступны все поля LLM: endpoint/ключ, model/model_ru/model_en, prompt и его
файл, temperature, лимиты токенов и инструментов, timeout_s, history_turns,
history_ttl_s, extra_body, listen_after_question и hold_response_ms.
Пропущенные поля наследуются после применения общих ALICE_LLM_* переменных.
Нулевые числа, false и пустые строки переопределяют значения явно;
extra_body заменяет словарь целиком, в том числе через `extra_body = {}`.
Если меняете model при общих model_ru/model_en, они по-прежнему наследуются;
чтобы убрать языковое переключение, задайте их пустыми строками.
При своём system_prompt можно убрать общий файл через system_prompt_file="".

ID сравниваются точно, с учётом регистра. Неизвестная колонка использует
общую секцию. Ошибки имён полей/секций профиля отвергаются при запуске.
Общие ASR/TTS-модели, timezone и список MCP-серверов остаются общими.
Профили и ключи применяются после перезапуска backend; SIGUSR1 меняет только
подробность логов. История и reset изолированы по устройству, включая
LLM-запросы внутри MCP-цепочки.

Device ID задаётся клиентом: это маршрутизация настроек и раздельный учёт,
а не самостоятельная аутентификация колонки.


## RU/EN-модели

```toml
[llm]
base_url = "http://host.docker.internal:11434/v1" # Docker Desktop → LLM на компьютере
model = "default-model"
model_ru = "russian-model"
model_en = "english-model"
max_tool_calls = 4
```

Внутри каждого профиля все три model ID обслуживаются одним `base_url` с одним API key. Это выбор модели на запрос, не ансамбль и не параллельные платные обращения. Кириллицы больше латиницы → `model_ru`; латиницы больше → `model_en`; ничья/числа/пустой маршрут → `model`. Выбранной модели добавляется указание отвечать на соответствующем языке. Смешанный текст обрабатывается эвристикой, не полноценным определителем языка.

Цепочка: аудио → ASR → распознанный текст → выбор LLM → ответ → TTS. Это **не** переключение ASR или голоса. Русская Vosk-модель не становится английской, Piper dmitri не превращается в английский голос. Для двуязычного ввода можно включить [Whisper auto](ASR_RU_EN.md); озвучке нужны соответствующие Piper-голоса. В echo-режиме внешние модели и MCP не вызываются.

## MCP

```toml
[mcp]
enabled = true

[[mcp.servers]]
name = "home"
url = "https://mcp.example.org/mcp"
token_env = "HOME_MCP_TOKEN"
# Необязательно: без списка или с [] доступны все инструменты сервера.
# allowed_tools = ["weather", "lights_status"]
```

Настройте только серверы, которым доверяете. По умолчанию разрешены все обнаруженные инструменты настроенного сервера. Непустой `allowed_tools` ограничивает доступ точными именами tools; отсутствующий список или `[]` не ограничивает его. Несколько `[[mcp.servers]]` поддерживаются. Секрет берётся из указанной переменной окружения процесса, не из ответа LLM. Для Docker передайте эту переменную контейнеру отдельно. Не кладите токены в URL или Git. HTTP разрешён только loopback; удалённые endpoints требуют HTTPS. `localhost` внутри Docker — контейнер, не Mac. Stdio/произвольные команды, устаревший HTTP+SSE transport и произвольные URL от модели не поддерживаются. Используется Streamable HTTP. Для HTTP endpoint требуется literal loopback IP (`127.0.0.1`/`::1`); имя `localhost` и HTTP на `host.docker.internal` не принимаются. Сервер вне network namespace quasard подключайте через явно настроенный HTTPS URL с корректным сертификатом. Для локального MCP без токена строку `token_env` можно убрать; если она задана, соответствующая переменная должна быть непустой.

### Автоматическая петля

1. На запрос обнаруживаются инструменты настроенных серверов с учётом опционального `allowed_tools`, имена разделяются namespace: `mcp_home__weather`.
2. LLM получает описания и схемы и выбирает один tool call. Сервер проверяет завершённость ответа, имя инструмента и JSON-аргументы по схеме.
3. Инструмент выполняется сразу: без голосового подтверждения, чтения параметров вслух и ожидания 90 секунд.
4. Результат возвращается той же модели. Она может вызвать следующий инструмент или дать окончательный ответ для озвучки.
5. Вся цепочка ограничена `llm.max_tool_calls` (по умолчанию 4, максимум 16) на исходный запрос. После исчерпания бюджета модель получает `tool_choice=none`; попытка обойти лимит отклоняется сервером.

**Инструменты могут менять внешние данные сразу после запроса, без дополнительного согласия.** Подключайте только доверенные серверы с нужными правами; для ограничения используйте `allowed_tools`. Описания и результаты tools считаются недоверенными данными, но это не гарантирует защиту модели от prompt injection. Сам quasard не запрашивает подтверждение; отдельный MCP-сервер может иметь собственную политику доступа. API оставляйте в доверенной сети.

При ошибке действия автоматического повтора нет: инструмент мог уже выполнить операцию, даже если ответ потерялся. Отмена запроса прерывает цепочку и передаёт отмену текущему вызову, но не откатывает уже выполненные внешние действия. Промежуточные предположения LLM не озвучиваются как факт исполнения. История диалога получает только успешный окончательный ответ.

### Ограничения

- До 8 серверов, 32 доступных tools, ограниченные discovery pages и размеры схем.
- MCP операция до 10 секунд, HTTP response до 1 MiB, аргументы и результат до 16 KiB; большие данные отклоняются, не молча обрезаются. Redirect запрещён.
- Параметры проверяются по обнаруженной inline JSON Schema. Любые `$ref`/`$dynamicRef`/`$recursiveRef` отклоняются (включая локальные); глубина/число узлов/ветвления ограничены. Внешние схемы не загружаются. Сложные серверные схемы могут быть несовместимы.
- Tool-enabled completion буферизуется до проверки `finish_reason`; усечённые/отказные ответы ничего не запускают. Обычный режим без MCP остаётся потоковым. Провайдер должен поддерживать `tools` и Chat Completions non-streaming.
- Параметры/результаты не пишутся в debug-лог. Они уходят настроенному LLM/MCP, но не озвучиваются отдельно — учитывайте их политики хранения.
- SIGHUP меняет только DNS. Для изменения LLM/MCP нужен рестарт backend.

## Диагностика

`server.log_level = "DEBUG"` теперь применяется к slog. DNS-журнал включается отдельно `dns.log_queries = true`; ограничения и приватность — [NETWORKING.md](NETWORKING.md). Полный protocol trace/запись аудио не включаются этим флагом.
