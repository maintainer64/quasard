# Диагностика своей Станции и импорт HAR

Только собственное устройство и сеть, где у вас есть разрешение на диагностику. Ниже нет инструкции по перехвату чужого трафика.

- [Запуск и основной рецепт Compose](../README.md)
- [Собственный CA и доверие Станции](STATION_CA.md)
- [DNS и ограничения сервера](NETWORKING.md)
- [DNS на Keenetic](KEENETIC.md)

Своя Станция Лайт уже работала с проектом, но полная совместимость функций, моделей и прошивок остаётся непроверенной. Успешный импорт или тест симулятора не закрывает [parity](parity.md).

## Сначала проверить без захвата

1. Запустите сервер по основной инструкции и проверьте локальную доступность.
2. Проверьте HTTP-активацию и WebSocket симуляторами.
3. Для реальной Станции отдельно проверьте DNS, нужные порты и доверие к CA. Если DNS уже отвечает правильно, ошибка TLS не исправляется добавлением доменов в rewrite.
4. Только затем решайте, нужен ли ограниченный захват одного сбоя.

Команды ниже выполняются из корня репозитория. Для установленных готовых бинарников используйте `quasard-tools` вместо `go run ./cmd/quasard-tools`. Вариант `go run` требует Go и зависимостей; при их отсутствии он может обратиться к сети.

Справка доступных инструментов:

```sh
go run ./cmd/quasard-tools activation-sim --help
go run ./cmd/quasard-tools station-sim --help
go run ./cmd/quasard-tools import-har --help
go run ./cmd/quasard-tools certs --help
```

Пример для уже работающего локального HTTP-сервера на 8080:

```sh
go run ./cmd/quasard-tools activation-sim --base http://127.0.0.1:8080
go run ./cmd/quasard-tools station-sim --url ws://127.0.0.1:8080/uni.ws --text "Привет" --out data/diagnostics
```

Это локальные примеры, не настройка реальной Станции. Явно задавайте endpoint: у `activation-sim` по умолчанию `https://127.0.0.1:8443`, у `station-sim` — `ws://127.0.0.1:80/uni.ws`. Текстовый тест не проверяет микрофон, ASR и слышимый ответ колонки; полный результат зависит от настроенных компонентов сервера.

При HTTPS/WSS оба симулятора по умолчанию не проверяют сертификат. Для проверки доверия нужен `--verify` и доверенный тестовый CA в окружении клиента. У `activation-sim` SNI берётся из логического имени проверяемого сервиса, а не из адреса `--base`. Не переносите отключённую проверку TLS из симулятора в настройки устройства или ОС.

Генерация сертификатов командой `certs` не устанавливает доверие на Станции. Создание собственного CA, установка и откат доверия описаны отдельно в [STATION_CA.md](STATION_CA.md). Не используйте чужие приватные ключи и не отключайте TLS-проверку глобально.

## Что сервер не записывает

`quasard` — не универсальный MITM/reverse proxy и не HAR recorder. Он отвечает на поддержанные запросы сам, а неизвестный HTTP-путь может получить мок `200 {"status":"ok"}`. Legacy-параметр `server.log_traffic` не включает реализованный полный захват трафика.

DNS-журнал содержит только метаданные запросов, без HTTP-содержимого, пакетов и идентификатора клиента. Он не показывает все соединения, не доказывает отсутствие облачного трафика и не удостоверяет, что запрос пришёл от Станции. См. [NETWORKING.md](NETWORKING.md).

## Если нужен захват

Используйте отдельно выбранное средство диагностики на своём устройстве или своём сетевом оборудовании. Ограничьте захват адресом Станции, нужным протоколом и коротким интервалом воспроизведения ошибки. Не собирайте трафик всей домашней сети ради одного запроса.

Обычный PCAP с зашифрованным TLS не содержит открытых HTTP-ответов для HAR-импорта. DNS rewrite не расшифровывает TLS. Доступность диагностики зависит от устройства, прошивки и pinning; установленный CA сам по себе не гарантирует возможность чтения трафика.

HAR, аудио и диагностические логи могут содержать OAuth-токены, cookies, пароли Wi-Fi, идентификаторы устройств, URL с секретами и личные разговоры. Храните оригиналы закрыто, собирайте минимум данных и удаляйте после диагностики. Не кладите их в Git, issue, публичные логи или CI artifacts. Не публикуйте ключи CA и серверов.

## Импорт уже полученного HAR

Импорт работает с локальным файлом и не воспроизводит запросы к облаку. Сначала проверьте источник HAR. Сделайте резервную копию существующих данных и выберите отдельный закрытый каталог: импорт может перезаписать одноимённые результаты.

```sh
go run ./cmd/quasard-tools import-har --out data/har-import capture.har
```

`capture.har` — ваш локальный файл, `data/har-import` — пример каталога результата. Импорт сам не переключает сервер на этот каталог; использование данных требует отдельного решения оператора.

Поддерживается ограниченный набор:

- JSON-ответы со статусом `200` для путей `/get_sync_info`, `/glagol/device_list`, `/get_user_details`, если запись не помечена `_mock`;
- ответы сохраняются в `captured/`; из `/get_sync_info` может обновиться запись `devices/` с данными `glagol`;
- из поддержанного HAR-расширения `_webSocketMessages` для `uni.ws` извлекаются отправленные бинарные аудиофрагменты в `samples/`.

Это не универсальный replay HAR: другие ответы не становятся автоматически обработчиками сервера, а произвольный формат WebSocket не гарантирован. Импорт не проверяет совместимость прошивки, настоящий OAuth, музыку или полный голосовой цикл.

Импортёр не отправляет содержимое HAR внешнему сервису, но **не обезличивает** его. Созданные JSON и аудио остаются чувствительными; исходный HAR тоже не удаляется. Перед передачей даже небольшого фрагмента вручную удалите токены, cookies, Wi-Fi, идентификаторы и личные данные. Для issue лучше приложить минимальный синтетический пример и описание ошибки без реальной записи разговора.

## Завершить диагностику

Выключите временный DNS-журнал, удалите временные ACL для диагностического компьютера и остановите отдельный захват. Если возвращаете Станцию на обычную сеть, **сначала восстановите DNS и переподключите её, затем останавливайте quasard**. Откат доверия CA выполняйте отдельно по [руководству](STATION_CA.md).
