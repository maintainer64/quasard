# Диагностика протокола своего устройства

Только своя Станция и разрешённая тестовая сеть. Реальные HAR/аудио могут содержать OAuth-токены, Wi-Fi, идентификаторы и личные разговоры. Не включать их в Git, issue, CI artifacts или публичные логи.

## Сначала проверить без перехвата

Go backend — не универсальный MITM/reverse proxy и не HAR recorder. Неизвестные HTTP-пути возвращают mock `200 {"status":"ok"}`. Флаг legacy `log_traffic` не означает, что полный traffic capture уже реализован. См. [NETWORKING.md](NETWORKING.md) и [parity.md](parity.md).

Для проверки локального протокола используйте Go `activation-sim`, `station-sim` и unit tests. TLS-сертификаты своего тестового CA генерирует `quasard-tools certs`; точные опции:

```sh
go run ./cmd/quasard-tools certs --help
go run ./cmd/quasard-tools activation-sim --help
go run ./cmd/quasard-tools station-sim --help
```

Генерация CA не устанавливает доверие на устройства. Установка CA/подключение реальной Станции требуют отдельного решения оператора; поддержка зависит от прошивки/pinning. Не используйте чужие либо скомпрометированные ключи публичных CA и не отключайте проверку TLS глобально.

## DNS и отдельный клиент

Для Keenetic — [KEENETIC.md](KEENETIC.md): отдельный DNS-профиль зарегистрированной Станции, точные rewrite, проверка других клиентов, откат. Не применяйте глобальный DNS hijack ко всем устройствам ради одной колонки. DNS rewrite не решает TLS и не превращает сервер в gateway.

## Если HAR уже получен законным способом

```sh
go run ./cmd/quasard-tools import-har --help
go run ./cmd/quasard-tools import-har --out data capture.har
```

Перед импортом проверьте источник файла. Импорт выполняется локально, не отправляет HAR внешнему сервису; сохраняет поддерживаемые captured responses в приватное хранилище. Исходный HAR и generated data храните закрыто. Импорт не воспроизводит реальные OAuth-запросы и не подтверждает аппаратный паритет.

Для нового HAR потребуется **отдельный** от quasard инструмент диагностики с явной конфигурацией upstream, TLS, DNS и разрешённым scope. Готового безопасного «прозрачного проксирования всех сайтов» проект сейчас не предоставляет. Не выдавайте DNS-подмену и фиктивные HTTP 200 за успешное общение с оригинальным сервером.
