# Диагностика задержек и распознавания

Новые события и SIGUSR1 доступны после сборки и деплоя версии с этой поддержкой.

## Постоянный DEBUG

В существующей секции конфигурации задайте:

```toml
[server]
log_level = "DEBUG"
```

Либо передайте контейнеру `ALICE_SERVER_LOG_LEVEL=DEBUG`. Изменение конфигурации
или Docker environment применяется после перезапуска backend.

## Временное переключение без перезапуска

На Linux/macOS после обновления бинарника:

```sh
cd /opt/quasard
docker compose kill --signal SIGUSR1 quasard
docker compose logs --follow --tail 100 quasard
```

Сигнал переключает DEBUG и уровень из конфигурации. Если в конфигурации уже
DEBUG, временное выключение переключает на INFO. Повторный сигнал возвращает
DEBUG. Событие `diagnostic logging changed` показывает выбранный уровень.
Сигнал не перечитывает конфигурацию и не перезапускает модели. Windows
использует настройку log_level и перезапуск; переключение SIGUSR1 там недоступно.
На старом бинарнике без обработчика этот сигнал использовать нельзя.

## Какие события искать

На INFO видны подключения/отключения станций и итог обработки ответа.
На DEBUG каждое событие содержит `device` и, для запроса, `request_id`:

| Событие | Что измеряется |
| --- | --- |
| voice input started / finished | Длительность записи, наличие речи и причина завершения |
| ASR started | Полная длительность аудио и длина выделенного для ASR фрагмента |
| ASR finished | Время распознавания, raw_text и text после удаления обращения «Алиса» |
| LLM turn started | Выбранный профиль, базовая модель, наличие MCP |
| LLM model selected | Модель после языкового переключения |
| LLM HTTP response | Ожидание HTTP-заголовков, статус и host без пути/параметров URL |
| LLM first token | Время до первого непустого SSE-токена; также указан выбранный model |
| MCP discovery / tool started / finished | Время обнаружения и выполнения инструментов, без аргументов и результатов |
| answer first phrase | Когда получена первая готовая для озвучивания фраза |
| TTS phrase ready | Время синтеза одной фразы |
| audio output started | Когда началась отправка звука в колонку |
| answer finished | Итог и общая длительность обработки |

При MCP ответы провайдера непотоковые: ориентируйтесь на HTTP response,
MCP-события и answer first phrase, а не на LLM first token. Время HTTP до
заголовков включает DNS/TCP/TLS и ожидание провайдера, а не только ping.
Время LLM turn может включать ожидание потребителя речи.

**DEBUG содержит распознанную речь**, включая исходный результат ASR.
На INFO текст распознавания не выводится. API-ключи, Authorization, содержимое
HTTP-запросов/ответов LLM, аудио и MCP-аргументы диагностический режим не пишет.
`server.log_traffic` — отдельная настройка; DEBUG её не включает.

Поздние аудиопакеты после закрытия входного pipe игнорируются без потока
`io: read/write on closed pipe`. Ошибки ASR, декодера и синтеза не скрываются.
Нехватку RAM проверяйте через Docker/cgroup OOM-счётчики, а не по closed pipe.
