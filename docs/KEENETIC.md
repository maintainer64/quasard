# Keenetic: направить DNS Станции на quasard

Эта инструкция меняет только DNS для своей Станции. Сервер и доверие к собственному CA должны быть готовы заранее. Настройка роутера не заменяет эти шаги.

- [Запуск сервера и основной рецепт Compose](../README.md)
- [Собственный CA и доверие на Станции](STATION_CA.md)
- [Как работает DNS quasard](NETWORKING.md)

Своя Станция Лайт уже работала с проектом, но это не подтверждает полную совместимость всех функций, моделей и прошивок. См. [границы проверки](parity.md).

## 1. Что подготовить

Перед изменением DNS проверьте:

- `quasard` уже запущен по основной инструкции. Его HTTP/TLS доступны Станции на нужных портах; сертификат сервера и доверие Станции настроены по отдельному руководству CA.
- У хоста постоянный LAN IPv4. Ниже он обозначен `HOST_IP`: это адрес компьютера с сервером, не IP контейнера и не `127.0.0.1`.
- DNS quasard доступен на `HOST_IP:53` по UDP и TCP, отвечает только разрешённым клиентам и не открыт в интернет.
- В DNS настроены точные имена `quasar.yandex.net` и `uniproxy.alice.yandex.net`. Их A-ответ — `HOST_IP`; при пустом `answer_ipv6` AAAA-ответ пустой, без ошибки. Остальные имена пересылаются upstream.
- Upstream DNS quasard работает независимо от этого перенаправления. Не направляйте запросы обратно на Keenetic, если тот отправляет их в quasard: получится цикл.

Запишите текущие DNS-настройки и профиль Станции, сохраните закрытую резервную копию конфигурации Keenetic. Оставьте доступ к роутеру с другого устройства.

Названия страниц зависят от версии KeeneticOS. Здесь важен результат — какой DNS получит Станция, — а не точная версия прошивки или путь по меню.

## 2. Выбрать, кому менять DNS

**Предпочтительный вариант — отдельный DNS-профиль своей Станции**, если роутер это поддерживает.

1. Найдите Станцию в списке клиентов. Проверьте MAC активного интерфейса: у Wi-Fi и Ethernet он может отличаться.
2. Зарегистрируйте устройство и закрепите его IPv4. Этот адрес нужен также для ACL DNS на сервере.
3. Создайте или выберите отдельный профиль с DNS-сервером `HOST_IP` и назначьте его Станции.
4. Проверьте, что автоматический DNS провайдера, интернет-фильтр, DoH/DoT или другой профиль не подменяют выбранную настройку.

Если отдельного профиля нет или нужен DNS для всех клиентов, оператор может указать `HOST_IP` в общих DNS/DHCP-настройках домашней сети. **Это затронет всю сеть**, а не только колонку: учитывайте доступность сервера, ACL и последствия блокировок. Такой вариант — осознанный выбор, не обязательное условие.

Не добавляйте публичный DNS вторым адресом «на всякий случай». Клиент может выбрать его не только при отказе первого и обойти локальные ответы. Отказоустойчивость требует второго резолвера с той же политикой; публичные DNS при необходимости задаются как upstream самого quasard.

Для этого сценария на Keenetic не нужны NAT/DNAT, статические маршруты, TLS-прокси или установка CA роутеру. Роутер выдаёт DNS-адрес; HTTP/TLS обслуживает заранее подготовленный сервер.

## 3. Переподключить и проверить

1. Примените настройки. Переподключите Станцию к сети или перезапустите её, чтобы обновились DHCP/DNS и старые соединения.
2. Проверьте назначенный профиль и полученный DNS в доступных сведениях о клиенте. Само сохранение настройки ещё не доказывает, что Станция её использует.
3. Проверьте ответы DNS по [инструкции](NETWORKING.md#проверка-dns). Для проверки с компьютера его адрес должен быть явно разрешён в ACL; успешный тест компьютера не доказывает путь DNS Станции.
4. Проверьте запуск, простой голосовой запрос, слышимый ответ и нужные вам функции. При необходимости временно включите DNS-журнал: он показывает имена запросов, но не удостоверяет источник и не доказывает успех TLS.
5. При отдельном профиле убедитесь, что другие устройства сохранили прежний DNS. При общей настройке проверьте также обычный доступ в интернет с других клиентов.

Если A-ответ правильный, а Станция не подключается, проверьте доступность HTTP/TLS, сертификат, время на устройстве и доверие к CA. Добавление новых rewrite не исправляет ошибку TLS. Рабочий DNS также не гарантирует голос, музыку или полную замену облака.

## 4. Откатить

**Сначала верните DNS, затем останавливайте сервер.**

1. Верните Станции прежний профиль или прежние DNS-настройки. Если меняли общие настройки, восстановите их для всей сети.
2. Переподключите Станцию, дождитесь обновления DNS и проверьте обычную работу. При общей настройке проверьте и другие устройства.
3. Только после этого отключайте DNS quasard, останавливайте контейнеры или убирайте публикацию портов по основной инструкции.
4. Выключите временный DNS-журнал и уберите временные разрешения для диагностического компьютера. Изменения доверия CA откатываются отдельно по [руководству](STATION_CA.md).

Если остановить DNS раньше, клиенты могут остаться без разрешения имён.
